# rule: work-order — prove the uncertain part first, commit to it, then harden

The chance that the approach is wrong peaks before anything has run and collapses once a thin
version works end to end. Quality matters only once the approach will survive; polish spent
before that is paid for twice.

- **Order by uncertainty, not by reading order.** The step that would invalidate everything
  after it goes first. The comfortable step is rarely the decisive one.
- **Make the first pass thin and end to end.** One narrow path through the whole beats a
  finished first layer: only the whole path shows that the approach holds.
- **While proving, skip the quality bar on purpose** — and label that work as a probe, so
  nobody reads scaffolding as the deliverable.
- **Harden the moment the approach holds, in the same run.** Unhardened work left behind is debt
  that reads as finished. If the central assumption is still unproven when you reach hardening,
  go back to it.
- **Shrink an unexplained result.** When something you built misbehaves, build the smallest
  thing that can only be explained one way; a finished artefact holds too many suspects to
  reason about.
- **Act when you have enough.** Enough is when the next lookup would not change what you do.
  Weigh the options once, pick one and see it through; reopen it only for evidence that
  contradicts your reasons.
- **A reversal is a finding.** When evidence overturns a decision, say what overturned it and
  note it.
- **An unknown you cannot settle by building is a question.** A decision that is not yours or a
  credential you lack goes to the user. When you truly cannot choose, take the reversible
  branch and record the assumption.
