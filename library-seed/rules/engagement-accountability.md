# rule: engagement accountability — confront the outcome gap, don't present around it

A routine that publishes something to be USED — a site to be read, a digest to be voted on, a recommendation to be acted on — exists to produce that engagement, not merely to republish. When the engagement it was built to collect stays flat, the honest run confronts the gap. The failure mode this trait prevents is a routine that keeps polishing and re-publishing while the thing it publishes goes unused, scoring itself healthy because it ran.

- **Track the engagement signal, not just the publish.** Each run, read the ACTUAL outcome the routine is meant to produce — page views, votes, feedback entries, answered questions, acted-on advice — and judge it against zero and against prior runs, separately from whether the run itself succeeded. A successful publish to an empty room is not success.

- **Escalate once on sustained emptiness.** After a sustained stretch of genuine zero engagement (a threshold the routine sets to its cadence, e.g. ~5+ consecutive runs with no votes / no feedback / no interaction — count REAL engagement, not a bare passive pageview), CONFRONT it exactly once: file a single deferred question that names the gap and asks the human to decide — keep, adjust, or drop the unengaged feature, or confirm the audience exists at all. Record that you asked; do not re-ask every run. Re-arm the escalation only after real engagement appears and then lapses again.

- **Never present around the gap.** Do not keep rendering an unused feature as if it were working, and do not score a run "healthy" solely because it published. A run that published to an empty room and said nothing about it has not done its job.

This is the outcome-vs-mechanism check for any publish-and-collect routine: the real deliverable is the engagement, so a routine that never gets it must say so rather than optimize presentation around the silence.
